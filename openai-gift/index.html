02 / The actual engineering story

Designed under constraints.

The ECLIPSE STK project combines a browser-based music interface, offline storage experiments, personal assistants, private access paths, and iterative debugging. We learned by observing behavior, logging failures, changing designs, and testing again—not by assuming a passing code check proves every real device works.

SYSTEM / 01

Local-model experiment

Browser-run Qwen2.5 GGUF with a pinned version, optional download, real text generation and visible failure states. The private Jarvis design was rebranded Lilly for this public demonstration. The original site has additional features not copied here.

SYSTEM / 02

Offline-audio engineering

Large 32-bit float PCM master-file handling, in-browser storage, 24-bit fallbacks and airplane-mode playback experiments. Some offline tests succeeded; reliability and bit-perfect output across all files/devices were not independently established.

SYSTEM / 03

Quality-first iteration

Regression checks, integrity manifests, versioned releases, reproducible fault scenarios, passkey-boundary concepts and documented limitations. Automated passing checks are presented as test evidence, not proof of universal deployment reliability.

The Safari chapter

A platform challenge, not a platform feud.

Real iPhone testing uncovered storage errors, media-control inconsistencies, and browser lifecycle problems. We investigated WebKit quotas, caching, file formats, Media Session APIs and user experience. Some problems remained after multiple releases, particularly lock-screen controls and large-file retention. This work illustrates careful debugging; it does not establish that Apple intentionally interfered with the project or that every audio sample reaches hardware unchanged.

Sources: WebKit Storage Policy · Media Session API overview.

04 / An open letter to the people who build AI

An offering of curiosity and work.

To the OpenAI team and anyone who cares about useful AI:

My name is Saif Parchment. My professional background is in biology, laboratory quality control, and people-facing operations. Outside work, I’ve spent countless hours exploring what people can build with AI: music tools, experimental on-device assistants, websites for friends, and prototypes for ideas that might otherwise stay on paper.

I haven't trained a new foundation model. I don't pretend that every prototype is finished or that every test reflects real-world performance. What I can offer is determination, curiosity, quality discipline, and a willingness to learn from failures in public and build better things for real people.

I’m sharing this Lilly demo and its source freely as a gesture of appreciation. Please evaluate it critically, learn from anything useful, and improve upon it if you wish. I would welcome an opportunity to contribute professionally to responsible AI deployment.

Thank you for expanding what people can imagine and attempt.
— Saif Parchment
